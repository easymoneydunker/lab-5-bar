# Практическое занятие 6. Исследование виртуальной памяти ОС Windows

Приложение на C# + Windows Forms (.NET 8), которое показывает, как Windows
организует виртуальную память процесса: системная информация, состояние памяти,
карта адресного пространства, резервирование и освобождение регионов.

## Как запустить

Нужен Windows и .NET 8 SDK (или Visual Studio 2022).

```
cd Lab6
dotnet run
```

Или открыть `Lab6/Lab6.csproj` в Visual Studio и нажать F5.

## Почему без WinAPI совсем нельзя

Задание требует функции `GetSystemInfo`, `GlobalMemoryStatus`, `VirtualQuery`,
`VirtualAlloc`, `VirtualFree`. Это функции Windows из `kernel32.dll`, у большинства
из них **нет аналогов в .NET**: например, .NET не умеет показать гранулярность
выделения памяти, границы адресного пространства или пройтись по регионам памяти.

Поэтому весь низкоуровневый код собран в **одном маленьком файле** `Native.cs`,
а снаружи с ним работают через обычные C#-классы: `record`, `enum`, `IEnumerable`,
`IDisposable`, LINQ. Форма вообще не знает про указатели и структуры WinAPI.
Там, где у функций Windows есть .NET-аналоги (`Environment`, `Process`, `GC`),
программа показывает их значения рядом, чтобы можно было сравнить.

# Теория

## 1. Виртуальное адресное пространство

Каждый процесс Windows работает не с физической памятью (микросхемами ОЗУ) напрямую,
а с **виртуальным адресным пространством** — диапазоном адресов, который
принадлежит только этому процессу.

* В 32-битной Windows указатель занимает 32 бита, значит адресов может быть
  2³² = 4 294 967 296, т. е. **4 ГБ**: от `0x00000000` до `0xFFFFFFFF`.
* В 64-битной Windows указатель 64-битный, а пользовательская часть пространства
  (на x64, Windows 10/11) — **128 ТБ**: примерно от `0x00010000` до `0x7FFFFFFEFFFF`.

Адресное пространство **закрытое (private)**: потоки процесса A видят только
память процесса A. Если процесс A хранит структуру по адресу `0x12345678`,
то процесс B по тому же адресу может хранить совсем другое — это просто
разные виртуальные адреса, которые отображаются на разные физические страницы.

Виртуальный адрес сам по себе ничего не хранит. Чтобы по нему можно было читать
и писать, система должна **связать** страницу виртуального адреса с физической
страницей (в ОЗУ или в файле подкачки). Это делает процессор с помощью таблиц
страниц, которые ведёт ОС. Обращение к адресу, не связанному с физической памятью,
вызывает **нарушение доступа (Access Violation)**.

**Отличие от физического пространства:** физическое — это реальные ячейки ОЗУ,
их объём ограничен установленной памятью и общий для всех. Виртуальное — это
«логическая» нумерация адресов отдельно для каждого процесса; её размер не зависит
от объёма ОЗУ, а реальная память выделяется только тем страницам, которые
действительно используются.

## 2. Разделы адресного пространства (32-битная Windows 98, по методичке)

| Диапазон | Размер | Назначение |
|----------|--------|-----------|
| `0x00000000`–`0x003FFFFF` | 4 МБ | Совместимость с MS-DOS и Win16. Нижние 4 КБ (`0x0000`–`0x0FFF`) недоступны — ловят обращения по нулевому указателю |
| `0x00400000`–`0x7FFFFFFF` | 2 ГБ − 4 МБ | Закрытое пространство процесса: код программы, куча, стеки, DLL |
| `0x80000000`–`0xBFFFFFFF` | 1 ГБ | Общие для всех процессов данные: системные DLL (KERNEL32, USER32, GDI32, ADVAPI32), проецируемые файлы |
| `0xC0000000`–`0xFFFFFFFF` | 1 ГБ | Код ОС: драйверы VxD, менеджер памяти, файловая система |

В Windows NT (и современных Windows) верхние 2 ГБ (а в x64 — всё, что выше
пользовательской части) принадлежат ядру и **недоступны** пользовательскому коду.
Узнать реальные границы пользовательской части на своём компьютере как раз
позволяют поля `lpMinimumApplicationAddress` и `lpMaximumApplicationAddress`
функции `GetSystemInfo` (задание 6.2.1).

## 3. Регионы, страницы, гранулярность

* **Страница** — минимальная единица, которой система управляет памятью:
  защита, передача физической памяти. На x86/x64 — **4 КБ** (`dwPageSize`).
* **Регион** — непрерывный участок адресного пространства, зарезервированный
  функцией `VirtualAlloc`. Размер региона всегда кратен размеру страницы.
* **Гранулярность выделения памяти** (allocation granularity) — граница,
  по которой выравнивается **начало** резервируемого региона. Сейчас это **64 КБ**
  (`dwAllocationGranularity`). Благодаря этому у системы меньше служебных записей
  о регионах и меньше фрагментация. Если запросить регион по адресу, не кратному
  64 КБ, `VirtualAlloc` округлит его вниз до кратного 64 КБ.

Сама система это правило для себя может нарушать: регионы под **PEB** и **TEB**
обычно не выровнены по 64 КБ, но их размер всё равно кратен размеру страницы.

### Состояния страниц

Каждая страница виртуального адресного пространства находится в одном из трёх состояний:

| Состояние | Смысл |
|-----------|------|
| `MEM_FREE` | Свободна, никем не занята. Обращение — нарушение доступа |
| `MEM_RESERVE` | Зарезервирована: адреса заняты (никто другой их не возьмёт), но физической памяти нет. Обращение — нарушение доступа |
| `MEM_COMMIT` | Передана физическая память (ОЗУ или файл подкачки). Можно работать с учётом атрибутов защиты |

### Типы памяти

| Тип | Смысл |
|-----|------|
| `MEM_IMAGE` | Страницы спроецированы из исполняемого файла (EXE, DLL) |
| `MEM_MAPPED` | Страницы спроецированы из файла данных (проецируемые в память файлы) |
| `MEM_PRIVATE` | Личная память процесса, поддерживаемая файлом подкачки (куча, стек, `VirtualAlloc`) |

## 4. PEB и TEB

* **PEB (Process Environment Block, блок окружения процесса)** — небольшая
  структура, которую система создаёт **в момент создания процесса**, сама
  выделяя под неё регион. В ней хранятся сведения о процессе: базовый адрес
  образа, список загруженных модулей, параметры командной строки, переменные
  окружения, указатель на кучу и т. д. Создаётся, управляется и уничтожается
  только ОС.
* **TEB (Thread Environment Block, блок окружения потока)** — аналогичная
  структура для каждого потока: границы стека, указатель на цепочку обработчиков
  исключений, номер последней ошибки (`GetLastError`), TLS-слоты. Регионы под
  TEB резервируются **при создании потока** и освобождаются при его завершении.

На карте памяти (вкладка «3. VirtualQuery») PEB и TEB видны как небольшие
регионы `MEM_PRIVATE` / `MEM_COMMIT` / `PAGE_READWRITE`, начало которых не
кратно 64 КБ.

## 5. Функция VirtualAlloc — резервирование и передача памяти

```c
LPVOID VirtualAlloc(
    LPVOID lpAddress,         // желаемый адрес региона (или NULL)
    SIZE_T dwSize,            // размер в байтах
    DWORD  flAllocationType,  // MEM_RESERVE и/или MEM_COMMIT
    DWORD  flProtect          // атрибут защиты PAGE_*
);
```

* **lpAddress** — где разместить регион. `NULL` — система выберет сама
  (обычно так и делают). Если задан адрес, например 50 МБ = 52428800,
  он округляется вниз до кратного 64 КБ; если там нет места — функция вернёт `NULL`.
  При передаче памяти (`MEM_COMMIT`) — адрес внутри уже зарезервированного региона.
* **dwSize** — размер региона; округляется вверх до кратного размеру страницы.
* **flAllocationType** — что сделать:
  * `MEM_RESERVE` — зарезервировать регион (занять адреса);
  * `MEM_COMMIT` — передать региону физическую память;
  * `MEM_RESERVE | MEM_COMMIT` — оба действия сразу.
* **flProtect** — атрибут защиты страниц.

Возвращает базовый адрес региона или `NULL` при ошибке.

**Передача физической памяти** (committing) — это второй вызов `VirtualAlloc`
с флагом `MEM_COMMIT` для уже зарезервированного региона (или его части).
Память всегда передаётся целыми страницами.

### Атрибуты защиты

| Атрибут | Что разрешено |
|---------|---------------|
| `PAGE_NOACCESS` | Ничего — любое обращение даёт нарушение доступа |
| `PAGE_READONLY` | Только чтение |
| `PAGE_READWRITE` | Чтение и запись |
| `PAGE_EXECUTE` | Только исполнение |
| `PAGE_EXECUTE_READ` | Исполнение и чтение |
| `PAGE_EXECUTE_READWRITE` | Всё |
| `PAGE_WRITECOPY` | Чтение; при записи процесс получает личную копию страницы (copy-on-write) |
| `PAGE_EXECUTE_WRITECOPY` | Всё; запись — с копированием страницы |

Дополнительные флаги: `PAGE_GUARD` (страница-«сторож», первое обращение
вызывает исключение — так растёт стек), `PAGE_NOCACHE`, `PAGE_WRITECOMBINE`.

## 6. Функция VirtualFree — возврат памяти и освобождение региона

```c
BOOL VirtualFree(
    LPVOID lpAddress,   // адрес
    SIZE_T dwSize,      // размер
    DWORD  dwFreeType   // MEM_DECOMMIT или MEM_RELEASE
);
```

* `MEM_DECOMMIT` — **возврат физической памяти** (decommitting): страницы
  снова становятся `MEM_RESERVE`, адреса остаются занятыми. Нужно указать адрес и размер.
* `MEM_RELEASE` — **освобождение региона** (releasing): возвращается вся
  физическая память и сами адреса, страницы становятся `MEM_FREE`.
  `lpAddress` — базовый адрес, который вернул `VirtualAlloc`, `dwSize` = **0**
  (система сама знает размер региона).

## 7. GetSystemInfo

Заполняет структуру `SYSTEM_INFO`:

| Поле | Смысл |
|------|------|
| `wProcessorArchitecture` | Архитектура: 0 — x86 (Intel), 5 — ARM, 6 — IA64, 9 — x64 (AMD64), 12 — ARM64 |
| `dwPageSize` | Размер страницы (4096 байт на x86/x64) |
| `lpMinimumApplicationAddress` | Минимальный адрес, доступный приложениям и DLL |
| `lpMaximumApplicationAddress` | Максимальный адрес, доступный приложениям и DLL |
| `dwActiveProcessorMask` | Битовая маска процессоров: бит 0 — первый процессор и т. д. |
| `dwNumberOfProcessors` | Количество логических процессоров |
| `dwProcessorType` | Устаревшее поле (386, 486, 586…), оставлено для совместимости |
| `dwAllocationGranularity` | Гранулярность выделения (65536 = 64 КБ) |
| `wProcessorLevel` | Уровень/семейство процессора (3 — 386, 4 — 486, 5 — Pentium, 6 — Pentium Pro и все современные Intel/AMD семейства 6) |
| `wProcessorRevision` | Модель и степпинг процессора в формате `xxyy` |

## 8. GlobalMemoryStatus

Заполняет структуру `MEMORYSTATUS`. **Перед вызовом обязательно** записать в
`dwLength` размер структуры — так Windows понимает, какую версию структуры ей дали.

| Поле | Смысл |
|------|------|
| `dwMemoryLoad` | Загрузка памяти в процентах (0 — свободна, 100 — занята полностью) |
| `dwTotalPhys` / `dwAvailPhys` | Всего / свободно физической памяти (ОЗУ) |
| `dwTotalPageFile` / `dwAvailPageFile` | Лимит выделяемой памяти (ОЗУ + файл подкачки) / сколько ещё можно выделить |
| `dwTotalVirtual` / `dwAvailVirtual` | Размер пользовательской части виртуального пространства процесса / сколько из неё свободно |

Чтобы **отслеживать** состояние памяти, функцию вызывают повторно (например, по
таймеру) и сравнивают значения: видно, как растёт загрузка, как уменьшается
свободное ОЗУ и т. д. В программе для этого на вкладке «2. GlobalMemoryStatus»
есть галочка «Обновлять каждую секунду» — она включает `Timer`, который раз в
секунду заново вызывает функцию.

## 9. VirtualQuery

```c
SIZE_T VirtualQuery(
    LPCVOID                   lpAddress,  // интересующий адрес
    PMEMORY_BASIC_INFORMATION lpBuffer,   // куда записать результат
    SIZE_T                    dwLength    // размер структуры
);
```

Возвращает число байт, записанных в буфер (0 — ошибка, например адрес вне
пользовательского пространства). Заполняет `MEMORY_BASIC_INFORMATION` сведениями
о группе **смежных страниц с одинаковыми состоянием, защитой и типом**,
начиная со страницы, содержащей `lpAddress`:

| Поле | Смысл |
|------|------|
| `BaseAddress` | `lpAddress`, округлённый вниз до границы страницы |
| `AllocationBase` | Базовый адрес региона, зарезервированного `VirtualAlloc`, в который входит адрес |
| `AllocationProtect` | Защита, заданная при первом резервировании региона |
| `RegionSize` | Размер группы одинаковых страниц, начиная с `BaseAddress` |
| `State` | `MEM_FREE`, `MEM_RESERVE` или `MEM_COMMIT` |
| `Protect` | Текущая защита страниц |
| `Type` | `MEM_IMAGE`, `MEM_MAPPED` или `MEM_PRIVATE` |

Для `MEM_FREE` поля `AllocationBase`, `AllocationProtect`, `Protect` и `Type` не определены.

**Обход всего адресного пространства:** начать с минимального адреса,
вызвать `VirtualQuery`, затем перейти к адресу `BaseAddress + RegionSize`
и повторять, пока не дойдём до максимального адреса. Так строится «карта памяти».

# Разбор кода

## Native.cs — единственное место с WinAPI

C# не может вызвать функцию Windows напрямую, поэтому её нужно **объявить**
через P/Invoke: атрибут `[DllImport("kernel32.dll")]` говорит .NET, что тело
функции находится в системной библиотеке.

```csharp
[DllImport("kernel32.dll")]
public static extern nuint VirtualQuery(nint address, out MEMORY_BASIC_INFORMATION info, nuint length);
```

Структуры `SYSTEM_INFO`, `MEMORYSTATUS`, `MEMORY_BASIC_INFORMATION` повторяют
C-структуры поле в поле; атрибут `[StructLayout(LayoutKind.Sequential)]`
гарантирует, что поля лежат в памяти в том же порядке, и Windows может их заполнить.

| C-тип | C#-тип | Почему |
|-------|--------|--------|
| `WORD` | `ushort` | 16 бит |
| `DWORD` | `uint` | 32 бита |
| `LPVOID`, `PVOID` | `nint` | Указатель: 4 байта в 32-битном процессе, 8 — в 64-битном |
| `SIZE_T`, `DWORD_PTR` | `nuint` | Беззнаковое число размера указателя |

`nint`/`nuint` — встроенные типы C# для чисел «размером с указатель». В методичке
поля размеров описаны как `DWORD`, потому что там 32-битная Windows 98; в современных
заголовках Windows это `SIZE_T`. Если описать их как `uint`, в 64-битной программе
структура «съедет» и значения будут мусором.

Интересный момент: в `MEMORY_BASIC_INFORMATION` поля `State`, `Protect`, `Type`
объявлены сразу нашими `enum`'ами (`MemoryState`, `PageProtection`, `MemoryType`).
`enum` с базовым типом `uint` хранится в памяти как обычный `uint`, поэтому
Windows пишет туда число, а мы сразу получаем удобное значение перечисления.

Класс помечен `internal` — его видно только внутри проекта, наружу он не «торчит».

## Models.cs — C#-модели

### Перечисления

```csharp
public enum MemoryState : uint { Commit = 0x1000, Reserve = 0x2000, Free = 0x10000 }
public enum MemoryType : uint { None = 0, Private = 0x20000, Mapped = 0x40000, Image = 0x1000000 }

[Flags]
public enum PageProtection : uint { NoAccess = 0x01, ReadOnly = 0x02, ReadWrite = 0x04, ..., Guard = 0x100 }
```

Вместо констант `MEM_COMMIT`, `PAGE_READWRITE` и т. д. — типизированные `enum`.
Значения совпадают с числами из `winnt.h`. Плюсы:

* нельзя случайно передать состояние вместо защиты — компилятор не даст;
* `ToString()` сразу печатает имя: `Commit`, `ReadWrite`, `Image`;
* `[Flags]` у `PageProtection` значит, что значения можно комбинировать битами,
  и `ToString()` выведет их через запятую: `ReadWrite, Guard` — это страница стека
  с флагом `PAGE_GUARD`.

Соответствие имён: `Commit` = `MEM_COMMIT`, `Reserve` = `MEM_RESERVE`,
`Free` = `MEM_FREE`, `Image` = `MEM_IMAGE`, `ReadWrite` = `PAGE_READWRITE` и т. д.

### Записи (record)

```csharp
public record SystemInfo(string Architecture, uint PageSize, ulong MinAddress, ...);
public record MemoryStatus(uint MemoryLoad, ulong TotalPhys, ulong AvailPhys, ...);
public record MemoryRegion(ulong BaseAddress, ulong AllocationBase, ..., MemoryState State, ...);
```

`record` — неизменяемый класс «для данных»: одной строкой объявляются свойства и
конструктор. В них лежат уже **понятные** значения (обычные `ulong` вместо `nint`,
строка вместо кода архитектуры), а не сырые структуры WinAPI.

Дополнительные вычисляемые свойства:

* `SystemInfo.ProcessorLevelName` — `switch`-выражение, перевод уровня процессора
  в название (3 → 80386, 4 → 80486, 5 → Pentium, 6 → Pentium Pro), точно как `case` в методичке;
* `MemoryRegion.EndAddress` — адрес сразу за регионом (`BaseAddress + Size`);
* `MemoryRegion.IsFree` — регион свободен;
* `MemoryRegion.ToString()` переопределён, чтобы регион красиво печатался одной строкой.

### Formatting — методы расширения

```csharp
public static string Hex(this ulong value) => "0x" + value.ToString("X" + IntPtr.Size * 2);
public static string Bytes(this ulong value) => value switch { >= 1UL << 40 => "... ТБ", ... };
```

Слово `this` перед параметром делает метод **методом расширения**: его можно
вызывать как будто он есть у самого `ulong`: `address.Hex()`, `size.Bytes()`.

* `Hex` — адрес в шестнадцатеричном виде, 8 цифр для 32-бит и 16 для 64-бит.
* `Bytes` — человекочитаемый размер. `switch` с шаблонами `>=` выбирает единицу
  измерения; `1UL << 30` — это 2³⁰ = 1 ГБ.

## VirtualMemory.cs — обёртка над функциями Windows

Статический класс, который делает из вызовов WinAPI обычные C#-методы.

### GetSystemInfo()

```csharp
Native.GetSystemInfo(out var si);
return new SystemInfo(ArchitectureName(si.wProcessorArchitecture), si.dwPageSize, ...);
```

Вызывает функцию Windows (она заполняет структуру `si` через `out`), а затем
перекладывает поля в `record SystemInfo`. Код архитектуры (0, 9, 12…) переводится
в строку `switch`-выражением `ArchitectureName`.

### GetMemoryStatus()

```csharp
var ms = new Native.MEMORYSTATUS { dwLength = (uint)Marshal.SizeOf<Native.MEMORYSTATUS>() };
Native.GlobalMemoryStatus(ref ms);
```

1. Создаём структуру и **сразу** записываем её размер в `dwLength` — этого требует
   документация (аналог `ms.dwLength := SizeOf(ms)` в Delphi).
   `Marshal.SizeOf<T>()` возвращает размер структуры в байтах.
2. Передаём по `ref` — по ссылке, потому что поле `dwLength` должно быть уже заполнено.
3. Перекладываем результат в `record MemoryStatus`.

### Query(address)

```csharp
if (Native.VirtualQuery((nint)address, out var mbi, size) == 0)
    return null;
return new MemoryRegion(...);
```

Вызывает `VirtualQuery`. Если функция вернула 0 (адрес вне пользовательского
пространства) — возвращаем `null`; поэтому тип результата `MemoryRegion?`
(знак `?` означает «может быть null»).

### GetRegions() — обход адресного пространства

```csharp
public static IEnumerable<MemoryRegion> GetRegions()
{
    var info = GetSystemInfo();
    var address = info.MinAddress;

    while (address < info.MaxAddress && Query(address) is { } region)
    {
        yield return region;
        address = region.EndAddress;
    }
}
```

Это и есть алгоритм построения карты памяти из теории:

1. Берём минимальный и максимальный адрес приложения (`GetSystemInfo`).
2. Спрашиваем `VirtualQuery` про текущий адрес — получаем блок одинаковых страниц.
3. Переходим к следующему блоку: `BaseAddress + RegionSize`.
4. Повторяем, пока не дойдём до максимального адреса.

C#-особенности:

* `yield return` — метод-**итератор**: регионы отдаются по одному «лениво», по мере
  перебора `foreach` или LINQ, без ручного создания списка.
* `Query(address) is { } region` — сопоставление с шаблоном: «если результат не `null`,
  положи его в переменную `region`». Если `VirtualQuery` вернёт 0, цикл закончится.

## VirtualRegion.cs — регион памяти как C#-объект

Класс оборачивает пару `VirtualAlloc` / `VirtualFree` и реализует `IDisposable`,
поэтому с регионом можно работать через `using`, как с файлом:

```csharp
using (var region = VirtualRegion.Reserve(64 * 1024))
{
    region.Commit(4096);
    region.WriteInt32(12345);
    region.Decommit(4096);
}
```

| Метод | Что вызывает |
|-------|--------------|
| `Reserve(size)` | `VirtualAlloc(NULL, size, MEM_RESERVE, PAGE_NOACCESS)` — резервирует регион |
| `Commit(size, protection)` | `VirtualAlloc(Address, size, MEM_COMMIT, protection)` — передаёт физическую память |
| `Decommit(size)` | `VirtualFree(Address, size, MEM_DECOMMIT)` — возвращает физическую память |
| `Dispose()` | `VirtualFree(Address, 0, MEM_RELEASE)` — освобождает регион целиком |
| `WriteInt32` / `ReadInt32` | `Marshal.WriteInt32` / `ReadInt32` — запись/чтение числа по адресу региона |
| `Info` | `VirtualMemory.Query(Address)` — текущее состояние региона |

* Конструктор `private` — создать объект можно только через `Reserve`, то есть
  только для реально зарезервированного региона (паттерн «фабричный метод»).
* Если Windows вернула ошибку, бросается `Win32Exception` — он сам берёт код
  ошибки через `GetLastError` (для этого в `DllImport` указано `SetLastError = true`).
* `Dispose` вызывается автоматически в конце блока `using` — даже если внутри
  произошло исключение. Поэтому регион невозможно «забыть» освободить.
  Флаг `released` защищает от двойного освобождения.

# Ответы на контрольные вопросы

**1. Что такое виртуальное адресное пространство процесса и чем оно отличается от физического?**
Это закрытый для других процессов диапазон адресов (4 ГБ в 32-битной Windows,
128 ТБ пользовательской части в x64), с которым работают потоки процесса.
Физическое пространство — реальная ОЗУ, общая для всей системы. Виртуальные
адреса отображаются на физические страницы через таблицы страниц; пока адрес
не связан с физической памятью, обращение к нему вызывает нарушение доступа.

**2. Что такое регион памяти и как он создаётся?**
Непрерывный участок виртуального адресного пространства, зарезервированный
для использования. Создаётся вызовом `VirtualAlloc` с флагом `MEM_RESERVE`;
начало выравнивается по гранулярности (64 КБ), размер — кратен странице.

**3. Что такое гранулярность выделения памяти?**
Величина, по границе которой выравнивается начало каждого резервируемого
региона (64 КБ, поле `dwAllocationGranularity`). Упрощает учёт регионов
и снижает фрагментацию.

**4. Как выполняется освобождение выделенного региона?**
`VirtualFree(baseAddress, 0, MEM_RELEASE)` — передаётся базовый адрес,
который вернул `VirtualAlloc`, размер 0. Возвращается и физическая память,
и сами адреса.

**5. Что такое блок переменных окружения процесса и как он создаётся?**
PEB — структура данных ОС с информацией о процессе (модули, параметры,
окружение, куча). Регион под неё система выделяет сама в момент создания процесса.

**6. Что такое блок переменных окружения потока и как он создаётся?**
TEB — структура ОС с информацией о потоке (границы стека, обработчики
исключений, код последней ошибки, TLS). Регион под неё резервируется при
создании потока и освобождается при его завершении.

**7. Как выполняется передача физической памяти выделенному региону?**
Вызовом `VirtualAlloc(адрес_внутри_региона, размер, MEM_COMMIT, защита)`.
Физическая память выделяется целыми страницами.

**8. Поясните параметры функции VirtualAlloc.**
`lpAddress` — желаемый адрес (`NULL` — выбирает система); `dwSize` — размер
в байтах; `flAllocationType` — `MEM_RESERVE` (резервировать) и/или `MEM_COMMIT`
(передать память); `flProtect` — атрибут защиты `PAGE_*`. Возвращает базовый
адрес региона или `NULL`.

**9. Как выполняется освобождение физической памяти, выделенной процессу?**
`VirtualFree(адрес, размер, MEM_DECOMMIT)` — страницы теряют физическую
память, но остаются зарезервированными. Либо `MEM_RELEASE` — освобождается
и память, и регион.

**10. Как использовать GlobalMemoryStatus() для отслеживания состояния памяти?**
Заполнить `dwLength = sizeof(MEMORYSTATUS)`, вызвать функцию и прочитать
поля: загрузку в процентах, общий и свободный объём ОЗУ, файла подкачки и
виртуального пространства. Для отслеживания вызывать периодически
(по таймеру/кнопке) и сравнивать значения.

**11. Поясните назначение и параметры функции VirtualQuery.**
Возвращает сведения о группе смежных страниц с одинаковыми свойствами,
содержащей заданный адрес. Параметры: `lpAddress` — адрес; `lpBuffer` —
указатель на структуру `MEMORY_BASIC_INFORMATION`, которую функция заполнит
(`BaseAddress`, `AllocationBase`, `AllocationProtect`, `RegionSize`, `State`,
`Protect`, `Type`); `dwLength` — размер этой структуры. Возвращает число
записанных байт (0 — ошибка).
